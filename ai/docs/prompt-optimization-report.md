# 시나리오 프롬프트 최적화 리포트

## 날짜
2026-02-08

## 요약
파인튜닝 모델(SKT A.X 4.0 Light 7B)과 GPT-4o의 시나리오 생성 프롬프트를 최적화.
6번의 변형 테스트를 통해 최적 프롬프트(v8)를 도출.

---

## 1. 문제 진단

### 원래 프롬프트의 출력 (MacBook Pro + 테크놀로지아 밈)

**파인튜닝 모델:**
```
scene1: (감탄) 테크놀로지아!
scene2: (기대) 이거 봐, 대단하지?
scene3: (놀람) 진짜 테크놀로지아!
scene4: (자신감) MacBook Pro, 지금 만나보세요!
```

**GPT-4o:**
```
scene1: (신나서) 테크놀로지아! (자신감) 이게 바로 M5 칩이에요!
scene2: (놀라며) 뭐야 이게! (신나서) 완전 빠르잖아!
scene3: (진지하게) 이 속도, 상상도 못했어요!
scene4: (신나서) 지금 바로 MacBook Pro를 만나보세요!
```

### 발견된 문제 3가지

| 문제 | 원인 |
|------|------|
| **스토리 전개 밋밋** | 4씬 내내 "감탄→감탄→감탄→CTA". 갈등/반전/빌드업 없음 |
| **밈 반복** | "최소 2개 씬에 걸쳐" 규칙이 밈 반복을 유도 |
| **대사 짧음** | 밈 문구만 단독으로 외침 ("테크놀로지아!" = 6자) |

### 근본 원인
프롬프트가 **포맷 준수**(글자수, JSON 구조, visual 5요소)에만 집중하고,
**스토리텔링 원칙**(빌드업, 클라이맥스, 감정 아크)에 대한 가이드가 없었음.

## 2. 테스트 방법

### 테스트 환경
- **모델**: RunPod Serverless vLLM (SKT A.X 4.0 Light 7B, QLoRA merged)
- **비교 모델**: GPT-4o (temperature=0)
- **테스트 스크립트**: `scripts/prompt_ab_test.py`

### 테스트 케이스
| 조합 | ad_id | 특징 |
|------|-------|------|
| 스팸 + 운동많이된다 | 3152 | 식품 × 운동 밈 (감정 밈) |
| 시원스쿨 + 핵심을찔렀어 | 3156 | 서비스 × 대사 밈 (문장형 밈) |

### 평가 기준
1. 대사 길이 (15~25자, 감정 태그 제외, 공백 미포함)
2. 밈 반복 여부 (scene3에서만 1회가 이상적)
3. 감정 아크 (씬별 감정 변화)
4. 밈 자연스러움 (문장에 녹아있는지 vs 단독 외침)

## 3. 변형 테스트 결과

### 결과 요약

| 버전 | 전략 | 문제수 | 핵심 발견 |
|------|------|--------|-----------|
| v3 | 예시 과다 | 3 | **모델이 예시를 그대로 복사** |
| v4 | 간결 | 8 | 7B 모델이 규칙 전부 무시 |
| v5 | 미니멀 | 5 | 글자수 부족 지속 |
| v6 | 규칙만 (예시 제거) | 5 | 글자수 부족 지속 |
| v7 | thinking 자기교정 | 6 | 7B 모델의 자기교정 능력 부족 |
| **v8** | **"2문장 이상" 규칙** | **3** | **"너무 짧음" → "약간 김"으로 전환** |

### 주요 발견

#### 발견 1: 예시를 넣으면 모델이 복사한다
v3에서 "(답답) 아 이거 로딩만 벌써 삼십분째인데 진짜"를 예시로 넣었더니,
**스팸 광고**에서 이 예시가 그대로 출력됨. 또한 "완전 테크놀로지아잖아!" 예시가
**운동많이된다 밈** 시나리오에 출력됨.

→ **결론: 프롬프트에 구체적 대사 예시를 넣지 말 것.**

#### 발견 2: 글자수 제약은 LLM이 못 따른다
"15~25자" 규칙을 v3~v7까지 다양하게 표현해봤지만,
7B 모델과 GPT-4o 모두 일관되게 8~13자 대사를 생성.

→ **결론: 숫자 기반 제약 대신 구조적 제약("2문장 이상")이 효과적.**

#### 발견 3: 간결할수록 7B 모델은 나빠진다
v4(간결), v5(미니멀)은 GPT-4o에는 괜찮을 수 있지만,
7B 파인튜닝 모델에는 규칙이 충분히 명시되어야 함.

→ **결론: 7B 모델용 프롬프트는 중간 길이(원칙 명확, 예시 없음)가 최적.**

#### 발견 4: Setup → Punchline은 효과적
모든 변형에서 "scene1 공감 → scene2 전환 → scene3 밈 폭발 → scene4 CTA" 구조가
기존 "밈부터 시작" 패턴보다 확실히 나은 결과를 냄.

→ **결론: Setup → Punchline 구조 확정.**

## 4. 최종 프롬프트 (v8)

### 핵심 변경 사항

| 항목 | 기존 | 최종 |
|------|------|------|
| 구조 | 밈이 스토리의 뼈대 (2씬 이상) | Setup → Punchline (scene3에서 1회) |
| 대사 길이 | "15~25자" (숫자) | "2문장 이상" (구조) |
| 예시 | 좋은 예/나쁜 예 다수 | 예시 없음 |
| 감정 | 미지정 | 씬별 감정 달라야 함 |
| thinking | 교체 테스트만 | 감정 아크 + 대사 초안 + 교체 테스트 |

### 적용 파일
- `content_pipeline/scenario/finetuned_client.py` → `FINETUNED_SYSTEM_PROMPT`
- `content_pipeline/scenario/prompts/generate_scenario_system_templates.py` → `GENERATE_SCENARIO_SYSTEM_TEMPLATE_V1`, `KZONG_SYSTEM_PROMPT_V1`

### v8 출력 예시

**스팸 + 운동많이된다:**
```
scene1: (답답) 아, 이 주방 정리 안 된 거 왜 이렇게 안 끝나? 벌써 한 시간째야.
scene2: (기대) 와, 이거 드디어 찾았다! 스팸의 그 유명한 팡팡 터지는 육즙이 기대된다.
scene3: (감탄) 이거 진짜 맛있다! 운동 많이 된다~ 이 육즙, 이 풍미!
scene4: (만족) 스팸, 한 번 먹으면 끝이야! 이렇게 맛있는 게 있다니!
```

**시원스쿨 + 핵심을찔렀어:**
```
scene1: (답답) 아, 외국어 공부 왜 이렇게 안 되지? 기본 문장도 못 만들고...
scene2: (기대) 시원스쿨을 알게 되니, 뭔가 새로운 기회가 생긴 것 같아.
scene3: (놀람) 와... 너 정말, 핵심을 찔렀어! 이게 진짜 된다고?
scene4: (만족) 시원스쿨, 기초부터 실전까지! 지금 시작해봐.
```

## 5. 알려진 한계

### 파인튜닝 모델 (7B)
- dialogue 필드에 JSON 찌꺼기가 섞이는 경우 있음 (visual_description, emotion 등)
- scene_type 값이 부정확 (모두 "close"로 출력) → 후처리로 보정 중
- 대사가 25자를 약간 초과하는 경우 있음 (26~31자) → 허용 범위

### GPT-4o
- temperature=0에서도 밈 활용의 창의성이 제한적
- 장소 일관성은 개선됨 (v8에서 4씬 동일 장소 유지)

### 공통
- 밈 자체가 짧은 감탄사형(예: "무야호")일 때, 2문장으로 자연스럽게 녹이는 것이
  여전히 어색할 수 있음
- 상품과 밈의 감정 연결이 약한 조합에서는 억지스러운 시나리오가 나올 수 있음

## 6. 향후 개선 방향

1. **파인튜닝 데이터 개선**: v8 프롬프트로 생성한 양질의 시나리오로 재학습
2. **후처리 파이프라인**: 대사 길이/품질 자동 검증 + GPT-4o 기반 리라이트
3. **밈 유형별 분기**: 감탄사형 / 문장형 / 동작형 밈에 따라 scene3 가이드 분기
4. **A/B 테스트 자동화**: `scripts/prompt_ab_test.py`로 프롬프트 변경 시 자동 비교
