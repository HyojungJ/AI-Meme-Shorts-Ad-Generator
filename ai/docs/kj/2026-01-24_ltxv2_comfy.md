## 개요
### 작업 내용
- LTX2는 원래 텍스트-이미지 입력만 지원하지만, 커뮤니티/오픈소스에서 공개된 ComfyUI 기반으로 오디오까지 받는 워크플로우 커스텀 노드/모델 설치 진행
- 참고: https://civitai.com/models/2306894?modelVersionId=2595561

### 주요 기능
1. ComfyUI에서 LTX-2 영상 생성용 **이미지 + 텍스트 + 오디오** 입력 워크플로우 구성
  - ComfyUI를 `/workspace/ComfyUI`에 설치
  - LTX-2 워크플로우에 필요한 커스텀 노드/모델 설치
2. `ltx2_workflow_v1.json`에 저장한 workflow JSON(API 포맷)과 로컬 파이프라인 연동
3. 입력 리소스 처리: 이미지 입력은 `/upload/image`로 자동 업로드, 오디오는 input 폴더 수동 업로드 (URL 방식 전환 필요)
4. output mp4 저장 및 메타데이터 기록

## LTX-2 ComfyUI REST API 실제 호출 구현

- **`/prompt`** : 워크플로우 실행 요청을 제출 (작업 등록)
- **`/history/{prompt_id}` :** 제출한 작업의 실행 결과 조회 (결과 조회)

1. 클라이언트가 요청을 보내면 API 서버가 작업 큐에 등록
2. 워커가 ComfyUI에 `/prompt` 전송
3. `/history/{prompt_id}`를 폴링하여 결과 출력 대기
4. 출력된 mp4를 다운로드하고 스토리지에 업로드
5. 비디오 URL + 메타데이터 반환

## 운영 모니터링 / 알림 전략
- **ComfyUI 상태**: `/system_stats` UI 응답, GPU 메모리 과부하 여부
- **큐 지연**: 요청에서 프롬프트 제출까지 시간 -> 급증 시 알림
- **작업 소요 시간**: 프롬프트부터 출력까지 시간 -> 최대 대기 시간 초과 시 알림
- **스토리지**: 업로드 실패, ComfyUI 호스트 디스크 공간 부족

## 트러블 슈팅
1. /prompt에서 class_type 누락 오류
원인: UI 저장 JSON(nodes/type)을 API에 그대로 전송
해결: **Save (API)**로 저장한 워크플로 JSON(class_type) 사용

2. 노드 누락(GetNode/SetNode/VHS 등)
원인: 커스텀 노드 미설치 또는 로딩 실패
해결: custom_nodes 설치 + 의존성(ffmpeg, opencv-python) 설치 후 ComfyUI 재시작

3. 오디오가 반영되지 않음
원인: ComfyUI가 `/upload/audio` 엔드포인트 지원 안 함
해결: 서버 `ComfyUI/input`에 오디오 파일을 직접 업로드. 차후 URL 방식 전환

4. history polling timeout
원인: 생성 시간이 길어 /history 응답 지연
해결: COMFY_MAX_WAIT_SEC 증가 + output 폴더에 mp4 생성 여부 확인
